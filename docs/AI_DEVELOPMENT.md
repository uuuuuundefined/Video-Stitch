# AI 开发执行说明

更新：2026-10-18，配套 PRD v1.1。产品规则已确认，当前会话已授权正式应用开发。新的实现与验证证据见 VALIDATION.md；历史样片已清理，不作为本轮实现的验收证据。

## 1. 开发约束

1. 每个阶段先说明交付与验证范围；必要的已授权局部实现不重复询问。
2. 需求优先级：最新明确决策 → PRD → 本文 → 原型。本轮最终决定见 DECISIONS.md，旧待确认条款已取代；新增业务取舍才重新确认。
3. 不创建账号、云端、遥测、自动更新、服务端、插件系统或长期后台守护程序。
4. 前端不处理视频二进制；Rust 负责媒体计划、进程和状态；FFmpeg/ffprobe 随应用分架构打包。
5. 演示资产列表、模拟进度和假环境状态不能进入正式业务运行路径；测试夹具仅用于后续实际验证。
6. 不把源视频裁短、变速或覆盖；空间裁剪只按已确认铺满规则实施。
7. 不把普通 `xfade` 重叠导致的时长损失掩盖为容差；必须使用经验证的边界补偿。
8. 新函数有简短用途注释；代码命名遵循项目约定；中文字符串保持 UTF-8。
9. 重要异常通过显式 Result/error code 传播，不伪造成功或默认媒体元数据。
10. 验证与改动匹配；不写只复述低风险实现的测试，也不因收尾无理由重跑全量。
11. 单页面、无预览、无缩略图、无业务磁盘缓存、无日志、无设置库；运行数据、错误详情、检测结果仅放内存。不得安装日志插件、创建诊断导出、使用 FFREPORT/-report 或将标准输出/错误重定向到文件。FFmpeg 错误只解析为有界、可操作的当前界面提示。
12. 卸载不扫描、不清理任何导出目录；其中正式视频、未完成视频和恢复记录均保留。任务正常完成/取消清理与卸载互不替代。
13. TypeScript strict；固定 Tauri 2 及依赖版本、锁文件和 FFmpeg 构建；使用项目统一格式检查、类型检查、Rust fmt/clippy 和与核心风险相称的测试。

## 2. 推荐模块边界

```text
React views → typed IPC → Rust application services
                         ├─ asset probe / fingerprint
                         ├─ plan builder / compatibility checks
                         ├─ engine candidates / process runner
                         ├─ queue / attempts / recovery
                         ├─ output reservation / validation / commit
                         └─ storage / embedded cleanup ownership rules
                                     ↓
                             ffprobe / ffmpeg sidecars
```

此为模块职责，不要求创建大量 crate 或提前抽象插件。只在共享契约明确时拆分文件；不在正式项目搭建前创建空壳目录树。

## 4. IPC 能力草案

| 命令 | 作用 | 重要约束 |
| --- | --- | --- |
| `import_assets` | 受限导入并异步探测 | 不复制原视频，不接受任意 shell 参数 |
| `remove_assets` | 移除集合引用 | 不删除文件，不修改既有任务快照 |
| `get_environment_status` | 获取真实检测状态 | 不虚构 GPU 或吞吐 |
| `plan_batch` | 返回组合数、阻断、空间及路径摘要 | 不启动编码 |
| `start_batch` | 用确认过的计划创建队列 | requestId 幂等，校验计划未过期 |
| `list_tasks` | 分页/游标获取任务 | 不一次返回全部十万项 |
| `pause_batch` / `resume_batch` | 调度暂停 / 继续 | 不声称可冻结单个编码进程 |
| `cancel_task` / `cancel_batch` | 取消、等待退出、清理 | 不删除成功结果 |
| `retry_tasks` | 产生新的 attempt | 成功任务不隐式重做 |
| `recover_batch` | 重新校验后恢复未完成项 | interrupted 单项从头执行 |
| `open_output` | 调系统打开成果或文件夹 | 确认输出归属及仍存在 |
| `get_performance_snapshot` | 获取当前真实性能快照 | 包含相关子进程；不支持字段返回 unavailable，不写采样文件 |
| `select_recovery_record` | 系统选择器选择输出目录中的恢复记录 | 不保存最近目录索引，不自动扫描磁盘 |

## 5. 错误语义

至少区分：`INPUT_MISSING`、`INPUT_CHANGED`、`PROBE_FAILED`、`UNSUPPORTED_STREAMS`、`INVALID_TIMESTAMPS`、`OUTPUT_NOT_WRITABLE`、`OUTPUT_CONFLICT`、`INSUFFICIENT_SPACE`、`ENGINE_UNAVAILABLE`、`HARDWARE_PATH_FAILED`、`PROCESS_FAILED`、`OUTPUT_INVALID`、`CANCELED`、`RECOVERY_REQUIRED`。

只有符合输入特征的硬件路径失败才触发处理路径回退。空间、输入丢失、权限和用户取消不是“换编码器就能解决”的错误，不能反复编码。

每阶段交付变更、验证命令/证据和未验证项。不得以“页面看起来完整”代替真实导出成功。

### 5. 文件导入与媒体探测

#### FR-01 两个独立输入集合

- A 组视频和 B 组视频分别添加、移除及清空。清空仅移除应用引用，绝不删除原文件。
- 同组内同一个规范化文件去重；不同路径但同名的文件允许同时存在。不能按名称去重。
- 同一个文件可以分别出现在两组；这种组合合法，不应偷偷跳过。
- 推荐保留导入顺序；批量生成的默认排序见 FR-03。
- 任务创建前可修改集合；创建后使用不可变快照，执行及暂停期间锁定本批次输入、参数和目录，不因前端重绘重建任务或丢失成功状态。
- 不把完整原视频复制进应用目录；仅保存引用及必要的元数据。

#### FR-02 探测与支持范围

- 首版重点覆盖 MP4、MOV 内的 H.264 / HEVC、普通 SDR 视频及常见 AAC / PCM / MP3 音频。封装扩展名不是支持结论，须探测实际流。
- 其他格式依据实际内置构建及测试矩阵决定支持，不承诺“FFmpeg 能读就全部稳定支持”。
- 每个输入显示名称、时长、文件大小、显示分辨率、方向和状态。技术细节放在详情里，不占主操作流程。
- 探测旋转、SAR/DAR、CFR/VFR、时间戳、像素格式、色彩/HDR、音轨、字幕/附加流、大小及修改时间。
- 处理 rotated / anamorphic 视频时以显示方向与显示比例计算画布，防止横竖颠倒或像素比例导致拉伸。
- 目录拖入首版提示“请导入视频文件”，不递归扫描整盘。损坏、加密、零有效帧或无视频流的文件明确拒绝。
- 探测失败仅影响该输入。不得以默认 0 秒、假分辨率或假音轨把它变成可执行任务。
- 多音轨、HDR、独立字幕按 D-03 阻断受影响任务并说明首版不支持；用户明确选择后，其余正常组合可以执行。烧录字幕视为画面。

### 6. 组合、计划与导出前校验

#### FR-03 全组合

- 全部组合数量为 A 组输入数×B 组输入数，另列可执行及受阻数量；异常输入不能从组合计数中消失。每个组合以两个稳定资产 ID 及批次 ID 标识，不能依赖文件名。
- 默认以 B 为外层、A 为内层：A01+B01、A02+B01、A01+B02、A02+B02，保持导入顺序。
- 大批量按分页/虚拟化显示，后端有界生成任务，关键状态只更新输出目录内恢复记录。计算组合数时检查整数范围，不能因前端数值溢出生成错误数量。
- 创建批次前展示有效输入数、被阻断组合数、总任务数；不能静默跳过坏文件。
- 数量、可执行/受阻数量及空间以页面摘要展示；旧 500 项强制确认建议未采用，不设固定数量上限，仍校验整数溢出与资源配额。

#### FR-04 导出前计划

- Rust 生成不可变执行计划：输入快照、画布、帧率、实际转场时长、音频方案、处理路径、输出路径、估计空间。
- 检测输入仍存在且未变化、输出目录可写、输出名无冲突、依赖可运行、磁盘空间足够。
- 文件变化后重新探测，旧计划失效，不能只更新路径而继续沿用旧时长。
- 预检结果分为阻断项和提示项；仅阻断有问题的组合，用户明确选择可执行部分后才能跳过阻断项。
- 流复制不兼容、空间估算、居中裁剪等提示集中在预检摘要，不为每个正常任务弹窗。
- 相同请求 ID 重复提交必须返回原批次，不得重复创建任务或导出文件。

### 7. 画布、裁剪与输出媒体

#### FR-05 画布

- 比例选项：跟随 B（默认）、9:16、16:9、1:1；分辨率、帧率自动跟随 B，无 1080p 上限和对应选择框。
- 先应用旋转并校正 SAR，使用 B 的有效显示尺寸。跟随比例沿用该尺寸；指定比例以显示短边确定目标：9:16 为短边×16/9长边，16:9 反向，1:1 为短边正方形。
- 指定有理数比例 p:q 时，为严格保持比例且满足偶数宽高，可取 k=2×round(min(Bw,Bh)/(2×min(p,q)))，尺寸为 (p×k,q×k)，k 至少 2。记录舍入后尺寸，不把任意偶数尺寸误标精确比例。跟随 B 的奇数/SAR 显示尺寸按媒体核心验证过的最小误差策略适配并提示实际输出。
- 例：B=3840×2160，9:16 输出 2160×3840，1:1 输出 2160×2160。小分辨率 A 铺满较大画布可能被插值放大。
- 画布配置由复制与转码路径共享，不得为走复制忽略用户选择。

#### FR-06 等比铺满

先应用显示方向、校正非方形像素，再按同一缩放因子覆盖输出画布，居中裁去溢出部分。不得分别缩放宽高，不使用黑色或透明填充。

源视频已有内置黑边不属于应用补边，首版不自动去除。透明通道且不能满足输出规则时明确阻断，不默默渲染黑底。设置区提示横竖转换可能裁掉人物或烧录字幕，不承诺主体识别或字幕保护。

首版不创建预览播放器、缩略图、接缝预览、磁盘代理或预览缓存。WebView 不支持的源编码仍由 ffprobe/FFmpeg 判断，不把浏览器媒体兼容性当作正式应用支持范围。

#### FR-07 输出格式

- 统一 MP4、H.264、8-bit 4:2:0 SDR、AAC（存在音轨时）；兼容优先。HEVC 输入转码，不保留 HEVC 输出例外。全程两段都无音轨时允许无音轨输出，不制造无必要文件。
- 输出帧率跟随 B 的可信有效有理数帧率。VFR B 先结合时间戳和有效平均帧率生成 CFR 计划，不只读 r_frame_rate；无法可靠判定则阻断并提示，不能默认随意取 30。
- A 或 B 转换到目标时间轴时允许帧重采样，完整保留有效播放时间区间、不改变速度。A=60、B=30 输出 30；提示可能降低 A 流畅度。VFR→CFR 不是逐帧无损。
- 不提供编码器、码率、硬件开关。各编码器质量参数分别校准，媒体基线阶段冻结质量映射、码率范围及画质阈值；“最优”须先满足画质和稳定性，不能只追求吞吐。
- 仅满足目标编码、格式、画布、帧率和流兼容契约的输入才可复制；音频不符时可视频复制、音频转 AAC。

### 8. 拼接与时间线契约

#### FR-08 不选择转场

- 直接顺接。UI 名称为“不选择转场”，不笼统承诺无损。
- 当无需画面/时间/音频变换，且编码、流结构、extradata、时间基、封装等经验证兼容时，优先流复制。
- 仅视频可复制但音频需规范化时，可采用视频复制＋音频重编码；不得因此误标“音视频完全无损”。
- 不兼容时自动选择转码，预检摘要显示“需适配画面 / 兼容参数，将重新编码”，不要求用户选择编码器。
- 不能仅检查扩展名、分辨率或编码器名称便决定可无损拼接。候选流复制路径失败时，可在未提交正式文件前有界回退到转码。

#### FR-09 定长边界叠化

默认请求时长 d=0.5 秒。首版只实现叠化，不实现擦除、滑动或闪黑。界面可只显示“叠化 · 0.5 秒”，不必增加可调时长控件。

历史样片采用的算法（正式实现须重新验证）：

1. 视频 A 时长 Ta，视频 B 时长 Tb，接缝在 Ta，总时长 Ta+Tb。
2. 在视频 A 尾端复制延展 h，视频 B 首端复制延展 h；叠化时长 2h，从 Ta−h 开始。
3. Ta−h～Ta：视频 A 仍按原时间播放，与视频 B 首帧混合。
4. Ta～Ta+h：视频 B 仍按原时间播放，与视频 A 末帧混合。
5. 延展长度恰好抵消重叠长度，不在两段中间额外插入片段，不对原视频变速。

离散实现：将视频规范化到有理数帧率 F；选取偶数转场帧数 N，左右各 N/2 帧。建议 N=2×floor(d×F/2)，实际时长 N/F，不得声称所有帧率下都精确为 0.500 秒。保持规范化后的 B 第一帧位于 A 结束后的原接缝时刻。短片令 hFrames=min(floor(d×F/2), max(0,min(aFrames,bFrames)-1))，N=2×hFrames；N<2 时直接顺接并提示，否则显示实际缩短时长。至少保留各段一帧非转场区，不能通过裁短或变速容纳转场。

过渡区画面必然混合，不能承诺每帧独立可见或原像素不变。不能偷换为“常规重叠叠化后加速/慢放补回时长”或“额外插入转场”。

#### FR-10 音频与时长

- 原音顺接，无交叉淡化、背景音乐或自动音量归一化，按已确认 D-02 执行。
- 音频从输入流的相对时间戳映射到该段时间线，不能把有意的延迟全部归零。
- 无音轨、短音轨、长音轨及多音轨的处理见 D-02、D-03。不存在音轨不等于该段视频应该被截短。
- 不得无条件使用 `-shortest`；不得用任意 `-t` 隐藏时间线错误。移除编码器 padding 不等于可删除真实内容。
- Ta/Tb 以可信的有效视频播放时间区间确定，不盲用容器 duration；元数据矛盾或异常时间戳需要进一步检测或阻断。
- D-02 的“明显长音”建议定义：剔除有证据的编码 padding 后，真实音频终点超出该段视频终点超过 max(2/F, 2048/R) 秒；边缘不确定而无法区分真实内容/padding 时先阻断。正常短音及起始延迟以静音补齐，不裁短视频。
- 建议时长验收：视频偏差不超过 2 个输出帧，容器偏差不超过 max(2/F, 2048/R) 秒，R 为输出音频采样率。正常音频规划应保持音画同步，不以该容差允许累计漂移。
- 样片特殊结论：60 FPS 的两个 5 秒输入输出精确 600 帧，视频/音频/容器均 10.000 秒。该结果不自动扩展为所有输入都逐帧无损。

### 9. 自动环境检测与性能

#### FR-11 环境及回退

- 启动快速异步检测系统、架构、应用内置 FFmpeg/ffprobe 及硬件候选；不阻塞导入。
- 需要编码时对候选执行有界短样本试编码，输出送管道或空设备；可用性只在本次内存复用，驱动/系统/二进制变化后失效，不生成测试文件或检测缓存。
- Mac 候选 VideoToolbox；Windows 按设备实际评估 NVENC、QSV、AMF。必须分别验证解码、滤镜、编码组合。
- “支持某硬件编码器”不等于可用，不等于所有步骤在 GPU 上运行，也不等于该路径总是最快。
- 选择顺序：正确性和既定质量约束 → 稳定性 → 实测吞吐及资源成本。允许更快的 CPU 解码＋硬件编码，不强制全链路 GPU。
- 回退候选有上限：当前失败路径不无限重试；输出残片清理后尝试下一已验证路径，最后允许软件编码。
- 状态可显示“自动加速 · 已就绪 / 检测中 / 兼容处理”，详情中解释原因，不展示编码器选择器。

#### FR-12 批量资源调度

- 不为 M×N 同时创建 FFmpeg 进程；任务按资源配额调度，初始保守并发，后续依真实测量调整。
- 同时考虑编码会话、显存、RAM、CPU、磁盘吞吐及外接盘带宽，失败或资源压力下减少并发。
- 文件探测结果和执行计划只在内存复用；不生成缩略图、长视频预解码缓存或规范化中间文件，不为复用重复有损编码。
- 任何后续提速也必须遵守无业务磁盘缓存；若需要额外落盘片段，则是范围变化，不能直接启用。
- 输入集合与队列虚拟化；事件合并，建议 UI 更新不超过每秒 5 次。不能把逐帧数据传给 React。
- 节流只影响显示，后台状态与最终成功事件不得丢失。
- 大批量空间估算应包含已完成输出、进行中临时输出、恢复记录及预留；区分估算和确定值，边执行边监控剩余空间。

#### NFR-01 性能验收方法

先建立基线，不在没有设备和代表性业务视频前承诺固定倍速。测试覆盖：可流复制、1080p 裁剪、1080p 叠化、4K、混合方向、批量重复输入。

记录机器/系统/驱动、输入详细参数、FFmpeg 构建、执行路径、并发数、冷/热启动、总耗时、输出校验、峰值内存/显存、临时空间和失败次数。至少重复 3 次报告中位数。相同质量标准下比较整体批次耗时，不仅比较单编码 FPS。

建议交互预算：主界面首屏 2 秒内可操作（参考设备冷启动，媒体探测不计入阻塞）；操作反馈 100ms 内；1 万任务不导致前端冻结。须在基线阶段冻结设备、数据集、指标及可接受误差，未达成时不得把建议值写成已通过。

### 10. 队列、取消及恢复

#### FR-13 状态机

`pending → preflight → ready → running → validating → committing → succeeded`

其他状态：`blocked`（需修复输入/空间/配置）、`failed`（执行或校验失败）、`canceling → canceled`、`interrupted`（上次执行中断）。

- 校验完成、正式文件原子提交并持久化后才进入 succeeded。
- 暂停是批次调度状态，不把正常执行任务伪装成“已暂停”：暂停后不启动下一项，当前任务继续完成。见 D-06。
- 取消任务必须终止对应进程及其受控子进程，等待退出后清理自有中间文件；不删除已成功输出。
- 用户取消即放弃，取消项不重试或恢复；编码回退不无限重试；手动重试生成新 attempt，当前错误只在内存保留，不建立历史日志。
- 失败重试仅针对失败/修复后的阻断项，不重新运行已成功项。

#### FR-14 进度和结果

- 单项显示当前阶段和进度；根据 FFmpeg 的有效输出时间计算，不使用随机数或假进度。
- 阶段包括准备、处理、校验；不能在编码进度 100% 时直接显示“完成”。
- 整体进度建议以计划工作量加权，完成数单独显示。剩余时间样本不足时显示“估算中”，并说明是估算。
- 每项显示两个源名称、目标名、预计时长/大小、目标分辨率、转场、状态、进度和适用操作；完成后显示实际时长/大小/分辨率。无法可靠估算显示暂无法估算，不能用固定压缩比例冒充准确大小。
- 错误给出用户能执行的动作：重新定位源文件、换目录、释放空间、重试。进程 stderr 只做有界解析以生成错误码/当前操作提示，不持久化或展示原始日志流。
- “打开文件 / 打开所在文件夹”仅针对已完成且仍存在的文件；不存在时明确提示。

#### FR-15 退出与恢复

- 每批次只在最终输出目录维护唯一的 `unfinished-tasks.<batchId>.json`（不覆盖同目录其他批次），关键状态更新用同目录短暂的原子替换记录，完成同步后及时清理旧代。禁止应用全局任务数据库、SQLite/WAL/SHM、历史库、最近目录索引或视频副本。
- 记录限于路径、拼接参数和任务状态及恢复必须的一致性字段：schemaVersion、batchId/taskId/attemptId、输入身份（大小/mtime 等指纹）、目标及临时相对路径、当前计划参数与提交阶段。不保存媒体二进制、逐帧进度、性能采样、原始错误、历史 attempts 或探测缓存。完成项最小状态只在同批仍有未完成项时保留，用于防止重做。
- 重启不自动知道自定义目录；用户手动选择恢复记录，先校验结构/版本/大小与条目数量，再重新授权输入和输出路径。不信任记录提供的任意删除路径，不跨目录清理、不跟随可疑符号链接。
- 正常退出停止当前进程并保存 interrupted；崩溃后 running/validating/committing 转 interrupted（先检查输出是否已提交）。已持久化取消意图的 canceling 必须完成取消清理并转 canceled，不能变回可恢复执行任务。
- 中断项从头处理；成功项不重跑；取消项不恢复。失败/阻断项保留，修复后可重试。整批仅剩 succeeded/canceled 时删除恢复记录；清理失败需提示具体路径，不能谎称记录已删。
- 恢复先核对源文件身份、当前计划版本、目录、空间及输出身份。重新定位需重新探测，源变更不能沿用旧计划；编码器在新会话重新选择。
- 正式视频与记录不能跨文件组成单一原子事务：提交前先把目标路径、唯一身份及 committing 阶段安全写进同一恢复记录，再改名并更新 succeeded。崩溃在两步之间时重新校验输出归属、媒体信息和指纹；不凭同名认领用户文件，不再复制或生成第二份成果。
- 部分成功项仍在记录时，恢复和清理不能删除这些成果；卸载完全不读取或清理导出目录。用户取消仅清理指定任务的可证明归属残片。失败残片重试前清理，退出/崩溃残片在手动恢复前重新核对归属。
- 关闭主窗口和退出均提供“暂不退出 / 停止并退出”，不进入托盘或后台；最小化不等于退出。休眠后检查进程、卷和硬件路径，不以墙钟推断处理成功。

### 11. 输出安全、命名及空间

#### FR-16 输出文件

- 默认使用系统桌面，在开始导出时建立唯一时间文件夹；保留原型现有初始文字和开始时更新规则。用户更改后直接使用选定最终目录，不再嵌套批次子目录。恢复/重试复用原目录。
- 建议文件名：`视频A文件名__视频B文件名.mp4`，同名增加 `(2)` 等后缀。去除跨平台非法字符、保留扩展名，限制路径长度，不丢失中文。
- 名称冲突处理考虑 Windows 保留名称、尾部点/空格、大小写不敏感文件系统及 Unicode 规范化；不能依赖 JavaScript 字符串不相等就认定可安全共存。
- 输出名在计划中预留；并发提交时仍使用“不覆盖”原子创建/提交，不能只在创建计划时检查存在性。
- 先在输出同目录直接写唯一 `.<taskId>.<attemptId>.partial.mp4`，显式指定容器，校验后在同一卷内以不覆盖方式原子改名。禁止复制完整文件、先在系统临时目录编码或额外 remux 到第二个完整视频；若优化封装，须证明不增加完整副本。
- 只允许清理由应用生成、可证明属于当前任务的临时文件。不得按通配后缀删除整个输出目录。
- 源文件与目标路径重合必须阻断。导出完成后不得通过“重试”覆盖用户后续修改的结果。

#### FR-17 空间

- 导出前检查输出卷空间、目录权限及可用性，执行中继续监测。
- 大批量、空间不足、磁盘拔出、权限撤回时停止调度受影响任务；明确保留已完成结果。
- 磁盘不足不进行无限自动重试。空间不足估算时允许更换目录或减少本次批量范围，但首版不提供组合编辑器。
- 文件大小估算具有不确定性，展示“预计”及预留，不能给出虚假的精确值。
- 不设置缓存/日志额度，因为不产生这些业务文件；进行中视频是唯一输出实例的一部分，估算不得同时当作正式视频再计一整份副本。

### 12. 隐私、清理、安装及卸载

#### FR-18 本地与权限

- 视频、音频和路径不离开本机。正式应用默认无远程字体、CDN 或分析脚本依赖。
- Rust 通过结构化参数调用固定应用内二进制，不拼 shell 命令；前端不能传入任意命令或 FFmpeg 参数。
- Tauri capability 与文件访问范围仅覆盖用户授权输入、输出及应用自有目录。
- 不写日志、诊断文件或业务设置；不使用 localStorage/IndexedDB/Service Worker/Cache API 保存业务数据。探测清单与媒体管线数据用内存/管道传递，单次进程异常转换为界面错误而非日志。
- 敏感路径不得放入不必要的错误上报或网络请求。无需网络权限也能完成首版主流程。

#### FR-19 数据清理与卸载

- 区分应用私有数据与任务数据。私有清单仅含应用、内置媒体二进制/库/字体/图标、WebView 自有运行目录、安装快捷方式/注册项；禁止凭文件后缀或整个用户目录推断归属；应用私有归属规则随包内置，不另建业务清理清单文件。
- 业务不创建预览、缩略图、日志、诊断导出、设置库、探测缓存、中间规范化视频或完成历史。唯一允许的业务落盘是输出目录内正式/进行中视频及恢复记录（含原子更新所需的同类短暂记录）。
- Mac 优先 nonPersistent WebView；Windows 验证 InPrivate/专属数据目录的实际落盘范围。登记实际创建路径，正常退出待 WebView 进程结束后清理；异常遗留由下一次启动及卸载方案处理。必须实测，不声称 incognito 自动等于整个引擎零文件。
- Windows 正常卸载移除安装包登记的 FFmpeg/ffprobe、私有库、当前安装范围自有 WebView 数据、快捷方式和注册项；停止受控进程后再清理。保留共享 WebView2/系统运行时。
- Mac 的 FFmpeg/ffprobe 随 .app 一起移入废纸篓，清空后释放；对 .app 外私有运行路径交付单独、可执行且限制归属的卸载清理方案/准确说明，不依赖拖入废纸篓触发应用代码。
- **卸载不得扫描、读取恢复记录以寻找或删除任何导出目录。目录内正式视频、未完成视频和恢复记录全部保留。** 它们属于用户任务数据；不因卸载或重装自动清理。
- 任务完成/取消时仍按 FR-15 清理恢复记录和残片，不能以卸载保留规则为由永久留存已结束任务记录；清理失败明确提示。
- 软件内不增加清理或卸载入口，不建立监视删除的常驻程序。原视频、系统记录、备份和其他用户数据保留。验收比较安装前后自有路径清单，并对卸载前后所有输出目录做不变性检查。

#### FR-20 打包与升级

- 目标构建：`aarch64-apple-darwin`、`x86_64-pc-windows-msvc`，分别内置适配的 FFmpeg 和 ffprobe。
- 开发期可以使用本机工具；交付包不得依赖用户 PATH 中的 FFmpeg、Node、Rust 或 Python。
- Windows 安装流程处理 WebView2 依赖。Mac 签名、公证和 Windows 签名按实际分发方式规划；生产交付验证安装、启动、组件可执行和卸载，试验包不能冒充已通过生产分发验证。
- 首版手动升级；升级不可删除用户成果，任务恢复格式迁移失败可回滚或停止恢复。
- 固定依赖和媒体二进制版本，保留构建参数、校验和及许可证。实际交付包必须满足其构建所涉及的许可义务。

#### FR-21 性能指标

- `get_performance_snapshot` 由 Rust 的平台采集适配层实现，每秒约一次，前端只接收聚合字段。软件进程集合包括主进程、归属 WebView、FFmpeg/ffprobe；需要处理短命进程、PID 复用和采样失败。
- 软件 CPU = 采样窗口相关进程 CPU 时间增量 /（窗口时间×逻辑核心数），统一整机 0～100%；系统 CPU 不是该字段。软件内存按可用的私有/物理占用口径报告并标明，不简单累加共享 RSS 冒充独占占用。
- 系统内存显示已用/总量。GPU 标明设备/引擎和实际采集口径；不能读到时返回 unavailable 并显示暂不可用，不能伪报 0 或将 3D 利用率代替硬件编码证明。
- 速度以短窗口内当前有效任务处理时间增量之和/墙钟时间表示 ×实时，不重复累加回退或 attempt 重做进度。ETA 使用剩余工作量与实测吞吐估算，准备/校验计入；异构任务样本不足显示估算中。
- 空闲无速度和 ETA；暂停停止倒计时，硬件检测/软件回退状态使用真实引擎结果。保留输出卷可用空间。所有采样及平滑窗口只放内存。

## 10. 历史验证结论与未验证项

- 用户于 2026-10-17 明确认可定长叠化样片。
- 历史样片、报告、对照图及生成脚本已按用户要求清理。以下结论来自清理前读取的验证记录；当前目录不保留可直接复查的原产物。正式开发时须重新建立测试夹具及验证证据。
- 输入：960×540 横屏和 540×960 竖屏，各 5 秒，60 FPS，自生成运动图形及测试音。

## 12. 原型维护约定

`prototype/index.html`、`styles.css`、`app.js` 为离线单页面原型，产品界面不显示示例/演示标签。内部静态素材、计时任务、恢复和指标仅用于状态检查，不连接真实后端或写任务文件；具体操作见 prototype/README.md。当前原型使用浏览器读取所选文件元数据，不能承诺 ffprobe 支持范围、真实路径去重、硬件检测或原生目录选择。

不得把此原型作为正式 React 业务代码复制后发布：移除状态夹具和模拟调度，接入真实类型化 IPC 与后端再验收。保留现有原型保存位置逻辑，不添加清理/卸载入口，不恢复联网 CDN、localStorage 或宿主状态持久化。
