## 一、目标与范围

本地、离线的视频全组合拼接工具。视频组 A 在前、视频组 B 在后，每个 A 与每个 B 组合。2×2 输出依次为 A01＋B01、A02＋B01、A01＋B02、A02＋B02，共四个独立视频。

不得截短源视频的播放时间区间、改变播放速度或覆盖原视频。已确认允许等比放大后居中裁掉画面边缘，以铺满输出画布；禁止拉伸和软件新增黑边。转场区域允许画面混合，帧率转换允许按输出时间轴重采样，不承诺逐帧或像素无损。

技术栈：React＋TypeScript＋Vite＋Tauri 2＋Rust＋内置 FFmpeg/ffprobe。支持 macOS 13+ 的 Apple Silicon Mac、Windows 10 22H2+ x64；首版不支持 Intel Mac、Windows ARM。

本基线的产品决策已经确认。后续发生新产品取舍才重新确认；不得沿用旧版“8 项待确认”状态。2026-10-18 当前会话已明确授权正式应用开发，实施状态与证据见 VALIDATION.md。

## 二、唯一页面与视觉

沿用已确认的黑白像素、简约终端风格原型，不重新设计风格。

| 位置 | 内容 |
| --- | --- |
| 顶部 | 产品名称、恢复任务入口 |
| 上部 | 视频组 A、视频组 B 两个独立导入区域 |
| 中部 | 将要生成的视频与同一批次的任务状态、进度、结果 |
| 下部 | 转场、画面比例、保存目录、开始导出及队列操作 |
| 底部角落 | 性能指标、自动处理状态 |

只有一个页面，不增加任务页、预览区、缓存管理页、清理或卸载入口。错误详情、预检和恢复使用当前页内提示或弹窗。长列表按需渲染，窗口缩放、高 DPI、中文长文件名及键盘操作均可用。状态用文字和图标区分，不只依靠颜色。

## 三、输入、组合及设置

### UI-01 视频组 A / B

- 每组支持多选和拖拽视频文件、逐项移除及清空。移除引用不删除原文件；不复制源视频。
- 显示文件名、时长、文件大小、显示分辨率、读取或异常状态。
- 同组按真实文件身份去重，不按“同名”或“同名且同大小”判断；同一文件允许分属 A、B 两组。
- 正式应用由 ffprobe 探测内容，不能以 WebView 是否能播放判断 FFmpeg 支持能力。首版重点支持 MP4、MOV 内的 H.264/HEVC SDR 及常见音频。
- 文件损坏、缺失、不支持或读取中有明确状态。文件夹拖入提示导入视频文件，不递归扫描。
- 批次开始后冻结输入、设置和输出位置，暂停期间也冻结；已有任务使用不可变快照。

### UI-02 组合与结果列表

- 数量为 A 数量×B 数量，按 B 为外层、A 为内层，保持各组导入顺序。
- 异常输入影响的组合仍需计数并说明原因，不静默过滤。开始前显示总组合、可执行及阻断数量，由用户明确选择是否先导出正常组合。
- 每行显示两个源文件名、输出名称、预计时长、预计大小、目标分辨率、状态、进度和适用操作。正式输出名使用 `A原文件名__B原文件名.mp4`。
- 大小只能估算时标“预计”，无法可靠估算时显示“暂无法估算”；完成后显示实际时长、大小和分辨率，禁止把两段文件大小相加当作准确输出大小。
- 列表大量组合时虚拟化或分页；不能一次建立同等数量的 FFmpeg 进程。

### UI-03 转场

- 默认“不选择转场”；另一选项为“叠化”，默认请求 0.5 秒。不增加其他转场或时长设置。
- 无转场按 A→B 顺接；仅在目标格式、画布、帧率和流结构都兼容时优先直接拼接，否则自动转码，不笼统宣称无损。
- 叠化采用定长边界补偿：A 尾段与 B 首帧混合，B 首段与 A 末帧混合。两段总时长保持 A+B，不加速、不慢放、不额外插入转场段。
- 短片自动缩短转场，无法构成有效转场时直接拼接并提示该组合的实际处理方式。
- 叠化必然混合画面，不保证过渡区每帧独立清晰可见。离散帧时长与允许误差见开发说明。

### UI-04 画面比例

- 选项：跟随视频 B（默认）、9:16、16:9、1:1。
- 每个组合按对应 B 的显示方向确定画布。先校正旋转和像素比例，再等比缩放、居中裁边铺满，不拉伸、不额外补边。
- 提示横竖转换可能裁掉人物或画面内字幕；首版不做人脸跟踪或手动移动裁剪中心。
- 源视频已有黑边不属于软件新增黑边，首版不自动去除。

### UI-05 分辨率与帧率

- 自动跟随对应视频 B，不增加分辨率、帧率选择框，不提供 1080p 上限。
- 跟随比例时沿用 B 的显示尺寸；指定比例时以 B 的显示短边确定画布，按编码器约束确定整数尺寸。例：B 为 3840×2160，选 9:16 输出 2160×3840，选 1:1 输出 2160×2160。
- 画面比例不等于固定像素尺寸；低分辨率 A 铺满 B 的较大画布时可能需要插值放大。
- 输出帧率跟随 B 的有效帧率。A 为 60 FPS、B 为 30 FPS 时输出 30 FPS，总时长不变，但 A 流畅度会降低；VFR 及异常帧率处理见开发说明。

### UI-06 不提供预览

不创建预览播放器、接缝预览、缩略图或预览代理，不生成相关磁盘文件。保留该编号用于追踪旧条款的移除，不作为待实现功能。

### UI-07 声音、特殊输入及输出兼容性

- 保留原声并按 A→B 顺接，无自动配乐、交叉淡化或音量归一化；不提供声音设置面板。
- 无声音或声音较短时补静音，不截短视频；保留音轨原有的有效起始延迟。
- 真实声音明显长于画面时提示并阻断该组合，不擅自裁音或延长画面。
- HDR、多音轨、独立可开关字幕首版提示不支持并阻断受影响组合；其他正常组合经用户明确选择可继续。烧录字幕属于画面，按画面规则处理。
- 统一输出 MP4 / H.264 / 8-bit 4:2:0 SDR / AAC（有音轨时）。仅符合此目标且无需其他变换时允许复制；HEVC 输入需要转码，不输出保留 HEVC 的例外文件。

## 四、导出与任务

### UI-08 保存位置与命名

- 默认在系统实际桌面目录中，开始导出时创建 `视频拼接_YYYY-MM-DD_HHmmss` 文件夹；同秒或同名冲突自动编号，不覆盖。
- 沿用已确认原型的目录逻辑：默认显示桌面时间文件夹；用户可更改本批次的最终输出目录，更改后直接使用该目录，不额外套一层子目录；重试或恢复不另建批次目录。
- 继续保留原型当前初始目录文字及开始导出时更新日期的行为，不因本次同步另改显示方式。
- 文件名使用两个原文件名（不含扩展名），同名自动增加编号。中文、Windows 保留名称、非法字符、Unicode、大小写和长路径均需处理。
- 每个进行中任务在输出目录直接写唯一临时视频，校验后原子改为正式名；不得另存或复制第二份完整视频。
- 已有文件、源文件和用户修改过的结果一律不覆盖。

### UI-09 开始导出及预检

- 显示组合数量、预计空间与开始导出按钮。A/B 任一组为空或全部组合不可用时禁用。
- 导出前检查源文件是否存在且未变化、目录可写、空间、依赖和执行计划；异常集中显示，部分执行需明确选择。
- 使用请求标识避免重复点击创建重复批次。开始后仍在本页显示进度，无页面跳转。
- 软件自动调度有限并发，默认硬件加速可用则采用合适路径；失败有界回退到其他可用路径或软件编码。不提供编码器和硬件开关。
- 规模提醒使用页面摘要，不新增未经单独确认的“500 项强制二次确认”门槛；后端仍检查数量溢出和实际空间。

### UI-10 状态、暂停、取消与重试

- 状态至少区分等待、预检、输入受阻、处理中、检查结果、已完成、失败、取消中、已取消、上次中断。
- 整体显示已完成数/总数和阶段进度；单项处理达到 100% 后仍需校验，成功提交后才标记完成。
- “暂停队列”让正在处理的任务完成，不再开始下一项；“继续导出”恢复调度，不声称暂停了单个编码进程。
- “取消”表示放弃指定未完成任务：停止对应进程、删除该任务自有临时视频、将其标记取消，不再重试或恢复。已完成视频保留。
- 想以后继续使用暂停或停止并退出。取消项仍可在本次列表中显示，但不能作为未完成项恢复。
- 只重试失败或已修复阻断项，不重跑成功项或取消项；单项失败不影响成功结果。
- 完成后提供打开视频/所在文件夹；文件已不存在时明确提示。

### UI-11 退出与手动恢复

- 有未完成任务时关闭窗口或退出，提示“暂不退出 / 停止并退出”；退出停止编码并保存必要恢复状态，不转后台常驻。
- 恢复记录只放在对应输出目录，名称包含唯一批次编号，不覆盖同目录其他批次的记录。重启后通过顶部“恢复任务”，由用户选择该目录中的记录；不保存最近目录索引，不自动扫描任意输出目录。
- 记录只包含恢复必要的文件路径、拼接参数和任务状态；任务标识、版本、源指纹和输出提交身份等必要一致性字段属于该记录，不包含视频副本、缩略图或日志。
- 恢复前重新检查源文件、目标文件、计划版本和空间。缺失文件可重新定位；源变化需重新探测，不能只换路径。
- 中断单项从头处理，先清理其可证明归属的残片；完成项不重做，取消项不恢复。失败/阻断项保留供修复和重试。
- 整批完成或全部剩余项已取消后删除恢复记录；正常任务清理失败须提示，不能伪报成功。
- 不承诺系统休眠期间处理；唤醒后检查进程、磁盘卷与硬件路径。

## 五、数据、环境与性能

### UI-12 数据边界与卸载方案（无界面入口）

- 业务只持久化导出视频、输出目录中的进行中临时视频和任务恢复记录（含安全原子更新所需的同类短暂记录）。不生成其他业务文件。
- 不建立磁盘缓存，不写日志，不保存预览、缩略图、诊断导出、设置数据库、完成历史或最近目录索引。媒体探测、检测结果、进度和性能采样仅放内存，关闭后释放。
- 拼接清单、测试编码结果等通过内存、管道或空设备传递，不落辅助文件。不将中间视频作为提速缓存。
- 界面引擎与安装组件的运行数据另列自有清单：优先非持久化运行，尽量减少不可避免的 WebView 数据，记录实际路径和退出/异常/卸载清理办法。不能未经双平台实测声称包外绝对零文件。
- FFmpeg、ffprobe 和私有依赖随包安装，不修改系统 PATH；Windows 卸载清单覆盖安装组件、自有运行目录、快捷方式和注册项。Mac 将组件放在 .app 内；应用包外自有运行数据提供可执行的卸载清理方案及准确路径，不依赖应用被拖入废纸篓时自行执行。
- **卸载不扫描、不清理任何导出目录。正式视频、未完成临时视频、恢复记录均是本次任务的数据，卸载时全部保留。** 这不改变任务完成/取消时的正常清理规则。
- Windows 将带归属标记的新私有运行目录排除为导出或恢复位置；旧版可能混有任务数据的运行目录不自动递归删除，不据文件后缀推断可清理归属。
- 原视频、共享 WebView2 等系统运行时、系统自行产生的记录及其他软件数据保留。不提供软件内清理/卸载按钮，不建立监听卸载的常驻程序。

### UI-13 自动环境适配

- 启动异步检测系统、架构、内置媒体组件和可用硬件路径，不阻塞导入。
- 以真实试编码和输入特征选择路径；正确性、既定画质和稳定性满足后，比较吞吐与资源成本。检测数据只在本次运行复用。
- 未验证时显示检测中；确认可用才显示自动加速就绪；软件回退显示兼容处理，不能伪报硬件已启用。
- 软件和原型均使用本地资源，无远程字体、CDN、遥测或账号依赖。

### UI-14 底部性能栏

| 指标 | 口径与显示 |
| --- | --- |
| 软件 CPU | 主进程、所属 WebView 与 FFmpeg/ffprobe 等相关进程；按整机总算力归一到 0～100% |
| 软件内存 | 上述相关进程内存，注明统计口径，不能只统计前端；不得把共享内存重复加和后冒充独占占用 |
| 系统内存 | 当前已用/总量 |
| GPU | 显示采集的设备/引擎含义，不能把 3D 使用率当作编码引擎占用；不支持时显示“暂不可用” |
| 导出速度 | ×实时；以短窗口内各任务新增有效媒体时长汇总/实际墙钟时长计算，不重复计入回退和重试进度 |
| 预计剩余时间 | 整批估算，包含准备/校验阶段；样本不足显示“估算中”，暂停时不继续倒计时 |
| 磁盘剩余 | 沿用原型，显示输出卷可用空间 |

指标约每秒刷新一次，空闲时速度/剩余时间显示“—”，不可获取的值不伪造为 0。采样只在内存中保留，不形成监控文件。

## 六、生产级开发与验收

- 按模块划分前端展示、类型化 IPC、Rust 探测/计划/调度/恢复/进程/提交/指标和 FFmpeg 适配层；不把业务逻辑塞进单个组件，不提前创建无用途抽象。
- 正式开发采用 TypeScript strict、统一 TS/Rust 契约来源、格式检查、类型检查和必要的核心/媒体集成测试；依赖与媒体构建固定版本。
- 必测：2×2、混合方向/分辨率/帧率、叠化时长、无声/短音/长音、异常输入、真实硬件回退、取消/暂停/恢复、磁盘异常、中文长路径、万项组合及双平台干净安装卸载。
- 每次导出做结构、媒体参数、时长、可播放性及安全提交检查；完整解码和接缝采样作为媒体集成测试，不无条件给每次导出增加第二遍完整解码。异常时按需扩大检查。
- 性能基线先固定参考设备、代表素材、画质策略和阈值，比较相同画质下整批耗时和峰值资源，不凭合成原型承诺倍速。建议首屏 2 秒内可操作、交互反馈 100ms 内、1 万任务不冻结；通过前须有实际证据。
- 实施、状态机、边界补偿公式、恢复一致性和 AC 清单见开发说明；需求优先级为最新明确决策→本 PRD→开发说明→原型。发现冲突先修正文档，不让旧原型代码覆盖已确认规则。

## 七、原型交付边界

原型是正式软件的界面与操作参考，界面去掉“示例数据”“交互演示”等提示，保留现有黑白像素风、初始内容和保存目录逻辑。底层整理为本地 HTML/CSS/JavaScript，无联网资源或本地状态缓存。

原型中的媒体列表、任务执行、恢复及性能状态仅用于交互检查，不包含真实 Tauri/Rust/FFmpeg 引擎，不创建输出视频或任务恢复文件。该边界只在开发文档说明；不得将原型的模拟进度、性能值、成功状态带入正式软件，也不得将本次原型修改当作媒体验收通过。

首版不做：预览、缩略图、1080p 档位、其他转场、时间线编辑、配乐、HDR/多音轨/独立字幕导出、主体跟踪、按名称配对、排除组合、云端、账号、自动更新、长期后台服务及软件内卸载入口。
