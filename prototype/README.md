# 产品原型

直接用浏览器打开 `index.html`。`styles.css` 保留已确认黑白像素终端布局，`app.js` 负责本地交互；无 CDN、远程字体、宿主桥接、localStorage/IndexedDB、Service Worker、布局缓存或额外依赖，无需安装包管理器。

界面采用正式产品文案，不显示“示例数据”“交互演示”等标签。静态媒体列表、任务调度、恢复选择流程及性能值仍是内存状态夹具：不连接 Tauri/Rust/FFmpeg，不生成视频、恢复记录、缩略图或日志，不证明真实导出、恢复或硬件加速已实现。这些代码不能进入正式应用。

## 状态检查

在打开的地址末尾加 `#state=状态` 后重新打开/刷新。状态切换不增加产品页面或工具条，不保存偏好：

| 状态 | 检查内容 |
| --- | --- |
| `empty` | 两组为空，禁止导出 |
| `ready` | 默认 2×2、四个组合、保存位置初始文字与原逻辑一致 |
| `running` | 一项完成、一项执行，暂停队列与取消 |
| `validating` | 单项进度 100%，状态仍为检查结果 |
| `paused` | 当前项已完成，设置锁定，可继续或取消 |
| `interrupted` | 完成项保留，中断项继续时从头处理 |
| `completed` | 成功结果及打开视频/目录入口 |
| `failed` | 只重试失败项，不重做成功项 |
| `blocked` | HDR 影响的组合仍显示，正常组合需明确选择才导出 |
| `canceled` | 取消项不恢复，主按钮只新建批次 |

running/validating 初始状态保持静止，点击取消或暂停可检查控件；点击暂停后自动推进在途任务直至暂停。默认 ready 点击开始导出会推进处理→检查→完成，耗时仅用于检查状态转换。

## 与正式应用的差异

- 导入会在内存读取用户选择的视频元数据并释放对象 URL，不复制媒体；浏览器不能读取的编码标为当前输入异常，不能据此判定正式 FFmpeg 不支持。浏览器无法获得跨平台规范化真实路径，去重只针对同一 File 引用，不误删同名同大小文件；正式去重由 Rust 文件身份实现。
- 保存位置仍使用原型路径文字输入。默认开始导出时按当前时间更新桌面批次路径；用户更改后直接用该最终目录。不会实际创建文件夹或选择原生目录。
- 恢复入口演练“手动选择记录→确认→中断状态”，只使用所选文件的名称，不读取或执行其内容，载入内存中已定义的中断场景。真实 JSON 恢复和源文件校验必须由 Rust 按开发说明实现。
- 完成大小、CPU/内存/GPU/速度为状态夹具；ETA 使用估算中，不显示编造倒计时。正式应用只能使用真实采样；无读数时明确 unavailable。
- 打开视频/目录按钮仅展示目标位置，正式应用需接原生打开接口。浏览器关闭不保存状态；正式应用退出需要按 PRD 保存输出目录内的恢复记录。
- 无清理/卸载入口。FFmpeg 安装、WebView 清理、卸载保留整个输出目录属于正式安装包与后端契约，不以原型交互代替验收。
